# 无尽巫师机制设计

## 当前实现补充（2026-11-04）

本节与当前试玩范围优先；后文保留此前的机制草案，不将草案当作全部已实现。具体113种内容及40条配方见同目录内容数据文档的“当前已实现内容目录”。

### 属性融合

- 火球与岩弹可相邻合成陨石术：延迟命中局部区域并附加灼烧。融合的火、土属性加成取平均，每种属性只计算一次；具体数值仍需试玩平衡。

### 召唤与建筑

- 法术定义声明实体生命、存续时间、行动/攻击方式、攻击间隔、同源数量与可选金币成本；编译仍统一叠加角色、装备、品质、途径和适用奥术，不另写一套战斗。
- 召唤物可以自动施放并移动追敌；建筑需要手动选址，提供攻击或恢复行为。装备相应法术后，玩家可在准备或奖励阶段部署；战斗中选址会先暂停，完成/取消后恢复进入选址前的状态。键盘方向键、回车、Esc与指针选址使用同一命令。
- 部署坐标为完整战场的0～100范围，不限制在防线附近。运行时同时验证角色归属、法杖装备、已知法术、冷却、法力、金币和数量；失败不扣资源，成功一次性扣费并进入冷却。相同命令ID不重复扣费或生成。
- 实体有生命，可被敌人攻击并摧毁；攻击发出的飞弹按真实路径结算，来源死亡不抹除已发射飞弹。击杀经验仍归来源角色。
- 实体仅随战斗时钟消耗寿命，暂停和准备不推进。清波与下一波保留仍存活的友方实体及剩余寿命，失败清除；存档使用已有单一运行时快照，不依赖UI另存实体。
- 原型保护上限为全场32个友方召唤/建筑、单次最多8个、同来源最多8个、寿命最长30秒，定义可设置更低值。上限属于当前性能保护参数，平衡仍待试玩。
- 新奥术覆盖穿透、迟缓、灼烧、震退、延时、容量与精准；仅修饰适用法术，穿透不会覆盖已有的溅射、连锁或落地区域。延时/容量受实体保护上限约束。

### 城墙边缘推进（2026-11-04修正）

此前仅将首波出生范围缩为30～70，无法覆盖后续全宽出生或已抵墙的旧存档敌人。直行与旧存档缺省路线在抵达y=92前保持原x下行；到墙后沿墙向最近的当前角色锚点推进，正常速度/加速/迟缓继续生效，并在冷却到期时继续攻击领地。追角色路线保留原规则；无角色时保留当前位置，不制造空目标，不增加随机抽样。此规则直接用于已有战斗状态，无需清空存档、改变角色射程或移除敌人。

### 装备、补给和怪物

装备为一格，通过角色槽位影响实际属性；补给覆盖固定或比例恢复生命/护盾/全队法力、同时恢复领地与推进法杖冷却，资源已满且无实际收益时不消耗。推进冷却不推进战斗、伤害或复活。普通怪随波次逐步加入，护甲、恢复、体积、追敌/直行与颜色按定义区分，Boss继续由波次出生计划安排。

### 本地解锁后的批量作弊（2026-11-04）

仅人类本地解锁且启用后生效，HTTP不能解锁。四类批量获取只补缺失定义，不替换旧实例或自动装备；批量目标等级目前为至少50，保留更高等级和品级，未创造新的物品等级效果公式。角色升级默认选定角色+1，协议允许每次1～100级，衔接个人累计经验、实际成长与法力恢复；不发放已跳过等级的历史赠品。调用仍使用统一命令幂等回执和存档，不在UI另写资源逻辑，不因打开设置自动执行。

### 运行和加载

战斗模拟与外部观察分开：内置已验证目录由运行时独占推进权威状态，减少每tick整份复制；公开纯函数和自定义目录保留复制路径。getState、checkpoint和每个订阅者仍获得隔离快照，通知在更新完成后发出。内置路径不提供意外内部异常的事务回滚保证；自定义目录抛错仍不提交部分模拟。

菜单、手册、角色、领地与天赋按需加载；PWA资源清单覆盖这些异步块，安装缓存完成后首次离线打开仍可用。首次加载不预加载全部菜单，窗口加载后Service Worker再缓存离线资源。常用符号以原字体小子集覆盖，极大扩展字体保留为按需回退，不在安装时强制预缓存。字体与依赖许可保持不变。

我们正在设计一款以法杖编排为核心的波次守城游戏。怪物向领地推进，玩家通过安排角色、法杖和法术组合，应对不断增强的敌人，并在战斗中获得新的构筑机会。

# 1 游戏定位与核心体验

**已确认**

- 借鉴生存类游戏的成长节奏，采用有轮次的守城玩法。

- 保留关卡概念，前期先提供一个无限关卡。

- 怪物从上方向下推进，到达领地后攻击。

- 玩家通过法杖槽位中的法术、奥术及符文组合，决定施法表现。

- 可获得多个角色；角色可以作为奖励；一个角色可以拥有多根法杖。

- 前期使用文字、图标和基础形状作为占位素材，后续可替换。

- 我们以 Inkra 使用方和游戏开发者的角度推进，组件库维护不属于这份游戏设计的范围。

**机制草案**
核心乐趣由三类决策构成：怎样拼装法杖；怎样把角色与法杖组合成队伍；怎样利用奖励和环境应对下一轮威胁。自动施法可以承担常规战斗，让玩家主要关注构筑和调整。

**待定**
自动攻击与手动操作的比例、战场宽度和路径数量、角色是否移动、局外成长、目标受众与单局时长。

# 2 队伍角色与法杖

**已确认**
构筑层级为：玩家控制的一方 → 多个角色 → 每个角色的多根法杖 → 各法杖上的法术布局。新增角色属于可能的奖励类型。

**机制草案**

- 区分角色定义与本局角色实例。两个同类角色也具有不同实例 ID，可保存各自的成长和装备。

- 每根法杖独立保存可用格子、物品位置、朝向和法杖特性。

- 角色特性可以影响本人法杖；队伍增益需明确标注作用对象。

- 原型可尝试“所有已装备法杖自动施法，每个角色共享自己的法力池”。这只是候选方案，多法杖的执行方式和法力归属仍待定。

- 暂存、上阵和装备应为不同状态。角色加入队伍不应自动打乱现有法杖。

- 奖励超出上阵或装备容量时，候选处理方式是进入候补区或待领取区，避免直接丢失。

**场景与处理草案**
| 场景 | 处理方案 |
|---|---|
| 得到新角色 | 展示角色特性和携杖能力，由玩家决定上阵或暂存 |
| 得到重复角色 | 先保留为独立实例；是否可升级、合并或换资源另定 |
| 把法杖交给另一角色 | 保留法杖布局，重新计算角色加成及可施放条件 |
| 卸下含有法术的法杖 | 作为整体保存布局；是否允许整体进入背包待定 |
| 多根法杖同时触发 | 按确定顺序执行，确保资源不足时结果可解释 |
| 角色受伤或阵亡 | 是否存在角色生命、复活与装备掉落规则待定 |

**已确认的背包归属**
背包为队伍共享库存；切换角色只切换其法杖与装备视图，不切换或复制库存。

**待定**
初始角色数、角色获取来源、上阵上限、候补容量、每角色携杖数量、角色站位，以及角色与领地生命的关系。

## 角色途径序列与晋升要素

**已确认**

- 角色具有晋升途径，途径中的序列前后依赖。

- 每条途径为不同序列提供各自的称号体系；相同序列号在不同途径中可以有不同名称与能力。

- 角色所处序列会对特定属性的魔法提供加成。

- 晋升需要完成并点亮对应升级要素，条件可以涉及装备、法杖、法术及其等级等。

- 仅提升角色等级不足以自动跨过所有序列。

- 早期“余烬术士、驭兽者、铸锋师”不作为最终角色称号，需按途径与序列重新命名。

**机制草案**
角色保留独立实例和姓名，途径表达其发展路线，当前序列表达身份与能力阶段。称号可以随晋升变化，角色身份、已装备法杖和背包归属保持连续。途径与元素不是必须一一对应，例如机巧途径可以使用金、火或雷属性的机关。

编号示例先采用9 → 8 → 7，数字方向、完整长度与更高阶段名称仍待定。一期可先实现每条途径三个序列，完整晋升流程与条件可配置，后续再扩展更高阶段。

### 序列对特定属性魔法的加成

**已确认**
角色所处序列会对特定属性的魔法提供加成。每条途径可以定义自己的亲和属性与适用效果，不只依靠称号和能力解锁区分阶段。

**机制草案**

- 序列定义亲和属性、受影响的效果、作用对象、加成值及条件。例如火系伤害、木系治疗、木系召唤生命、金系建筑输出分别配置，不把加成统一解释为所有属性一起增加。

- 建议作用于该角色施放或生成的内容，覆盖其所有适配的已装备法杖；队伍光环需要另外的能力声明。

- 直接法术、持续伤害、召唤物与建筑分别声明继承规则。生成实体的攻击若已经继承序列加成，命中时不能再次重复应用同一来源。

- 建议每个序列保存该阶段的最终亲和加成，晋升时替换同组旧值。例如从火系伤害加成5%提升到10%，当前结果为10%；继承的关键技能则按能力配置处理。

- 加成依照实际属性与效果标签计算，不根据技能名称、图标或颜色判断。双属性效果、跨系继承和与其他倍率的叠加顺序仍待定。

- 角色等级、法杖、奥术修饰与序列加成分别显示来源；晋升预览展示原值、新值和实际适用对象。

- 其他属性是否有使用限制仍待定；推荐先允许跨系编排，由序列亲和体现专长。

- 序列加成在晋升成功时与称号和能力一起生效，普通 Agent 只读取当前玩家有权知道的加成与下一阶段预览。

**待定**
各序列的亲和属性、数值、是否强化召唤或建筑、是否存在双系途径、条件型加成、同组叠加规则、等级与序列间的成长分工，以及是否允许少量不按数值递增而改变行为的序列效果。

### 等级序列与品级的分工草案

角色等级用于日常属性培养；途径序列承载职业称号、特定属性魔法加成、关键能力和能力上限。角色原有品级机制如何与序列衔接需要重新确认，建议优先让序列表达角色阶位，避免默认再增加一套必须并行培养的角色品质轴。是否还保留同序列下的资质或稀有度待定。法术、奥术和法杖仍分别保存自己的等级与品级，不随角色晋升自动提升。

### 三类晋升要素草案

| 类型 | 示例 | 完成方式 |
|---|---|---|
| 永久成长要素 | 学会已发现的技能、完成专长节点、通过指定挑战 | 玩家达成条件并点亮节点，保存完成记录 |
| 晋升时的实时条件 | 本角色装备至少一根指定等级法杖、装配指定等级法术 | 节点展示当前状态，晋升提交时重新检查 |
| 实际消耗 | 金币、材料，或明确要求献出的物品 | 预览明确列出，晋升成功时一次扣除 |

每个要素可以有前置节点。第一版可支持“全部满足”和“任选其一”两种组合，避免必须拿到唯一随机掉落才能继续。必需节点、可选专精、消耗节点应在界面中区分。是否支持失败概率、仪式小游戏或随机副作用尚未确定，原型建议先采用可预期的条件晋升。

### 晋升流程草案

查看途径与下一序列 → 查看前置节点及条件 → 培养法术或法杖并调整装备 → 主动点亮可完成的要素 → 必需节点与实时条件全部满足 → 预览消耗及能力变化 → 确认晋升。

晋升条件必须声明检查范围：本角色、本角色已装备法杖、全队或背包持有。另一个角色的高等级法术不能默默满足本角色的装配条件。“装备”“持有”“曾经掌握”是不同条件；满足装备条件不等于要消耗装备。

提交时统一校验原序列、条件和费用。成功后一次改变序列并授予对应能力；失败、取消或重复请求不重复扣费。正在移动或合成的物品不能产生半完成的晋升状态。

### 装备变化与其他边界草案

- 已点亮的永久节点和实时装备条件分别保存。装备被卸下后，永久节点保留，依赖当前装备的条件变为未满足。

- 建议晋升完成后不因临时卸杖自动降序列。某项能力如果需要持续装备，单独显示其启用条件。

- 晋升若要求消耗某件装备或法术，必须明确选中实例并说明其法杖布局如何处理，不能把达标物品默认当祭品。

- 角色晋升的称号和序列变化不重新生成角色 ID，也不复制等级、装备或已领取奖励。

- 同途径角色可以分别成长；跨途径转修、多途径兼修、角色奖励直接提供高序列和成长追赶规则待定。

- 新序列的能力可以增加携杖位或改变玩法，但具体效果需要各途径单独定义；不默认每序列都增加法杖数量。

- 晋升可先放在准备或背包暂停阶段，具体允许阶段待定。

- Agent 使用游戏声明的查询、点亮要素和晋升能力；只能读取已允许披露的途径节点与条件，不通过晋升预览解锁全部隐藏内容。

### 命名与一期内容草案

| 暂定途径 | 序列9称号 | 序列8称号 | 序列7称号 | 构筑方向 |
|---|---|---|---|---|
| 薪火途径 | 执烛人 | 燃灯者 | 守焰人 | 火焰、持续输出与火灵联动 |
| 生息途径 | 拾种人 | 育灵者 | 牧灵人 | 生命召唤、持续治疗与照料 |

这些名称是重新命名的草案，不是定名，也不照搬既有作品的完整途径表。其他学派后续可形成自己的称号体系；途径也可以融合多个属性或学派。

**待定**
完整序列数量与编号、各途径称号、初始途径选择、分支或转修、角色品级与序列的关系、要素点亮费用、装备条件的检查时机、晋升费用、是否消费指定物品、失败与副作用、奖励角色的序列起点，以及局内和局外保存范围。

## 角色升级与品级

**已确认**
角色也具备升级机制与品级机制。角色可以作为奖励，一个角色可以持有多根法杖。

**机制草案**
角色等级用于日常属性培养；关键身份与能力变化由途径和序列晋升承载。原先将品级主要解释为资质的方案需与序列体系重新对齐，角色品级是否直接由序列表达仍待定。具体命名、节点与效果见途径晋升章节。

角色成长可以影响以下方面，并按角色专长选择其中几项；不建议每个角色都在所有维度同时增长。

| 成长方向 | 可影响的属性或能力 | 对玩法的意义与适用条件 |
|---|---|---|
| 施法输出与辅助 | 法术伤害倍率、治疗量、护盾强度 | 强化该角色施放的内容，基础法术等级仍单独计算 |
| 施法节奏 | 施法速度、冷却恢复、特定条件下的额外触发 | 额外触发作为专长候选，不默认每级增加次数 |
| 资源管理 | 法力上限、回复、消耗效率 | 在采用法力系统后支撑高消耗和多法杖构筑 |
| 操控与元素专长 | 射程、范围、控制持续时间、特定元素效果 | 形成金木水火土光暗雷风等属性专长，以及控制、召唤、建造或治疗等分工 |
| 多法杖协调 | 携杖上限、切换或轮转效率、不同法杖之间的协同 | 携杖数量宜作为少量关键节点候选，避免每级扩大整套火力 |
| 召唤专长 | 精灵或动物的生命、伤害、治疗、持续时间、可维持数量或指挥范围 | 影响本人法术召唤的精灵或动物，是否作用于建筑需另外声明 |
| 建造专长 | 建筑耐久、攻击、修复或辅助效果、存续时间、可建造数量 | 区分防御建筑与攻击建筑，不默认共享全部召唤加成 |
| 生存能力 | 角色生命、防御、减伤或恢复 | 仅在角色可受攻击且有独立生命时启用 |
| 队伍支援 | 给队友的光环、资源支援、保护领地的技能 | 明确对象、距离、重复角色和多来源叠加规则 |
| 构筑便利 | 特定法术适配、装备条件或特殊布局奖励 | 不默认改变法术形状、品级或法杖格子 |

**成长分工草案**
法术和奥术成长强化具体内容，法杖成长强化载体，角色成长表达持有者的专长与组合方式。角色升品不自动给其法杖、法术升品，具体联动只能由明确的能力提供。最终效果应能查看来自角色、法杖、法术和奥术的各项贡献。

**场景处理草案**

- 已确认角色独立经验，当前新招募角色从1级0经验开始；后期是否按招募阶段追赶仍待设计，不再使用共享经验池。

- 相同角色的实例分别保存等级与品级；是否允许消耗重复角色培养另一个角色待定，不能连同装备静默销毁。

- 法杖换人后按新持有者重算角色加成，保留法杖和法术自身的成长。

- 角色升级不默认补满生命或法力；升级、治疗和补给分别结算。

- 被动光环、召唤和建筑需要明确归属；角色离场、换杖或成长后，已有实体是否实时变化须统一选择。

- 角色等级、个人经验与此前击杀升级奖励之间的关系仍待定，不能无意间把同一份经验或奖励重复发放。

**待定**
角色升级资源、经验分配、等级上限、关键等级、途径与序列、品级衔接、晋升要素和特性分支、重复角色用途、后加入角色的追赶、队伍光环叠加、携杖数量解锁、是否跨局保留。

# 3 单局与波次流程

**已确认**
每轮存活且消灭全部怪物后结算奖励，玩家可以调整法术，也可以进入下一波。轮次持续增加，敌人逐渐增强。

**机制草案**
一局可以按“初始准备 → 战斗 → 本轮结算 → 构筑调整 → 下一轮”推进。战斗中的背包编辑是额外的暂停入口，不必等待本轮结束。

轮次完成需要同时满足：本轮出怪计划结束、场上仍计入本轮的敌人数量为零、失败条件未触发。只清掉当前一批敌人不能提前结算。领地生命归零可作为原型失败条件；最终失败与复活规则待定。

| 阶段 | 时间推进草案 | 主要操作 |
|---|---|---|
| 初始准备 | 暂停 | 查看角色、配置法杖、开始本轮 |
| 战斗 | 推进 | 观察战况、施法、获取经验和掉落、打开背包 |
| 背包编辑 | 暂停 | 移动法术、调整法杖、在法杖上合成 |
| 本轮结算 | 暂停 | 查看收益、领取与选择奖励 |
| 波间准备 | 暂停 | 整理构筑、配置角色与装备、开始下一轮 |
| 本局结束 | 停止战斗 | 展示结果，后续是否支持继续或复活待定 |

**边界处理草案**

- 本轮结算只提交一次，重复打开结算界面不重新抽取或发放奖励。

- 持续伤害击杀、召唤物击杀和同时死亡，统一进入同一套击杀结算。

- 敌人卡住时不应直接认定已清场，需要恢复路径或提供游戏内处理方式。

- 暂停状态下的“开始下一波”必须明确处理当前编辑与待领奖励，不静默丢弃。

- 同时发生领地归零和最后一只敌人死亡时，按统一结算优先级处理；先判负还是先结算待定。

# 4 法杖槽位与背包编辑

**已确认**

- 法杖用于承载施法内容，背包保存暂时不用的内容。

- 合成只能发生在法杖上，背包内不能合成。

- 打开背包时暂停游戏，用于调整法术。

- 法术可占用不同数量和形状的格子，包括异形。更强的法术通常占用更多空间，具体形状结合特点设计。

- 战斗中一律锁定布局的早期建议已被“打开背包暂停调整”更新。

**机制草案**

- 形状由实际占用格子的集合表示，不以矩形包围盒代替。L 形的空角仍可容纳其他单元。

- 放置前检查边界、可用格、重叠和当前编辑权限；预览同时显示有效格与冲突格。

- 支持以 90 度为单位旋转。是否支持镜像由物品规则决定。

- 移动采用完整提交：放置成功才改变位置；取消或失败保留原位置。

- 打开背包暂停战斗模拟，包括敌人移动、伤害、施法冷却和临时状态计时。界面动画可以继续。

- 奖励弹窗、背包和其他暂停来源分别记录。关闭其中一个界面，不会解除仍由其他来源维持的暂停。

- 多个 Agent 或玩家同时操作时，需要明确当前控制者或通过状态版本检测冲突。

**待定**
法杖初始网格、异形可用区域、槽位扩建、背包是否也按格子摆放、背包容量、编辑期间角色换装限制、关闭背包时未放置物品的处理。

# 5 法术奥术与施法规则

**已确认**
法术提供施法效果，奥术可以改变周围法术的行为。双倍奥术能够让上下左右相邻的法术获得双倍调用效果。

**机制草案**

- 区分主动施法、被动修饰和提供资源的单元；“奥术”不必全部限制为被动增幅。

- 相邻按实际占用格的共边关系计算，斜角不计。

- 同一个奥术接触同一物品多个格子时，只建立一条作用关系。

- 第一版可限定常规相邻增幅在同一根法杖内生效，跨杖和跨角色增幅需要专门的能力。

- 布局修改后重新计算影响关系，并展示最终伤害、触发次数、冷却、消耗和作用来源。

- 常规增幅不互相无限触发。额外施法是否再次触发其他效果，应有明确的触发来源和次数上限。

- 攻击目标离场时重新选择合法目标；没有目标时是否消耗冷却和法力待定。

- 临时获得或失去法杖时，运行中的弹道和状态按照各自生命周期继续处理，具体归属另定。

**双倍奥术叠加候选**
| 情况 | 尚需选择的规则 |
|---|---|
| 一个双倍奥术影响一个法术 | 每次触发施放两次，具体间隔待定 |
| 两个双倍奥术影响同一法术 | 每个增加一次，或倍率相乘；尚未确定 |
| 额外施法的资源消耗 | 每次独立耗蓝、整组统一耗蓝或其他方案 |
| 法力不足以完成整组 | 整组等待、尽量施放或取消剩余次数 |
| 奥术相互相邻 | 是否作用，以及如何防止循环 |

**待定**
法力是否为首版资源、资源属于角色还是法杖、自动瞄准策略、施法距离与范围口径、暴击和元素抗性、攻击打断与法杖执行顺序。

## 可扩展的元素与法术学派

**已确认**

- 属性体系可扩展。当前在金、木、水、火、土基础上加入光、暗、雷、风；不把基础体系封闭为固定五系。

- 金、木、土三系有偏向建筑的魔法。

- 各系都提供召唤对应元素精灵的法术，当前覆盖金、木、水、火、土、光、暗、雷、风。

- 木系拥有更多召唤技能和治疗技能。

**机制草案**
属性是内容归属与专长标签；直接施法、召唤、建造、治疗、控制是玩法类型，两组维度分别表达。同一系可以支持多个玩法类型，建筑偏向不等于只有金木土可以拥有建筑。新增系别通过内容配置接入，保留统一的成长、配方、信息披露与调用机制。

| 系别 | 内容倾向草案 | 建筑候选 | 精灵行为候选 |
|---|---|---|---|
| 金 | 锋锐、穿透、机关输出 | 箭塔、剑阵台 | 金灵以飞刃或金针远程攻击 |
| 木 | 动物与精灵召唤、治疗、持续生长 | 木栅、荆棘塔、生命树 | 木灵治疗符合条件的友方 |
| 水 | 减速、冲退、流转支援 | 首批不强制配置建筑 | 水灵施加减速并辅助控场 |
| 火 | 爆发、范围、灼烧 | 首批不强制配置建筑 | 火灵进行范围攻击或附加灼烧 |
| 土 | 防御、地形、阵地 | 石墙、镇地台 | 土灵近身作战，承伤或阻挡须相关机制支持 |
| 光 | 即时救援、护盾、净化与保护 | 光辉灯塔候选 | 光灵为受威胁的合格友方提供护盾 |
| 暗 | 诅咒、削弱、汲取与持续侵蚀 | 首批不强制配置建筑 | 暗灵攻击并施加削弱效果 |
| 雷 | 连锁、多目标爆发与短时打断 | 导电机关作为后续候选 | 雷灵攻击可跳跃到邻近敌人 |
| 风 | 推退、聚拢、投射物与机动支援 | 首批不强制配置建筑 | 风灵推退敌人或辅助移动单位 |
| 冰分支候选 | 寒意、冻结、冰晶防御 | 冰墙候选 | 冰灵积累寒意并制造短时控制窗口 |
| 毒分支候选 | 叠层持续伤害与有限传播 | 首批不强制配置建筑 | 毒灵远程附毒；另有毒蜂动物召唤 |
| 奥术学派候选 | 魔弹、蓄力、资源管理 | 奥能法阵的实体类型待定 | 奥术精灵提供稳定输出 |
| 空间学派候选 | 合法部署、转移与弹道出口 | 折射门节点的实体类型待定 | 空间精灵短距转移自身并攻击 |
| 时间学派候选 | 局部行动、冷却与延时效果 | 首批不强制配置建筑 | 时灵提供局部节奏控制 |
| 亡灵学派候选 | 白骨军团、尸骸利用与魂灵役使 | 墓碑候选 | 魂灵提供远程输出；家族分类待定 |

## 各系差异与混合构筑草案

木系偏持续治疗、动物与精灵支援、活体建筑；光系偏即时治疗、护盾和应急保护。两者可以有功能重叠，但角色专长、施法节奏和构筑代价应体现差异。

金系偏直线穿透与机关输出，雷系偏目标间跳跃与短时爆发；水系偏减速和区域控制，风系偏推拉、聚拢和移动支援；火系持续伤害偏灼烧区域，暗系持续影响偏诅咒和削弱。这些是内容分工草案，不限制每系只能拥有一种效果。

混合构筑可以尝试水系潮湿与雷系攻击、风系位移与火系区域、光系护盾与木系召唤、土系阵地与金系机关。具体反应、倍率和配方需要逐项确认。光系显影或探知若在后续加入，只通过明确的游戏能力更新玩家知识，不因此向普通 Agent 开放全量隐藏资料。

**分类与联动草案**

- 元素精灵与动物都属于召唤物，可进一步区分精灵、动物等家族；它们与建筑分别拥有类型和容量规则。

- 木系以数量更多和功能更丰富体现召唤与治疗优势，例如动物攻击、动物治疗、精灵辅助、直接治疗和活体建筑。

- 角色、法杖、法术、奥术及符文可声明属性适配；是否限制跨系装备或施法仍待定。

- 品级和等级独立于属性分类，不把某一系默认设为更高品级。

- 五行相生相克、光暗互动、水雷或风火等属性反应、元素抗性、双系配方与跨系奖励都作为候选机制；加入新系不自动启用克制倍率或免疫。

- 雷击与连锁闪电归入雷系，风刃归入风系。冰、毒、奥术、空间、时间已补充独立章节的内容与机制草案；冰是否独立于水、毒与木暗的关系、后三者是否作为特殊学派仍待定。冰箭、冰霜新星和奥术弹保留既有 ID，按扩展分支重新组织便于讨论。

- 建筑的法术属性、建材和效果分别描述。木系治疗是否能作用于生命树等活体建筑需明确声明，不自动等同于修复金属或石质建筑。

**待定**
属性归属是否唯一、是否允许双系、跨系装备限制、各系反应或克制、精灵与动物是否共用召唤容量、木系额外召唤与治疗的具体比例、升级与品级如何改变属性特性、冰毒奥术空间时间是否独立成系，以及寒意、毒层、资源、合法转移和局部时间规则。

## 冰毒奥术空间时间的扩展设计草案

本节把五个候选方向细化为可讨论的机制，并不代表已经确定五者全部独立成系或同时进入首版。冰可以继续作为水系分支，毒可以与木暗产生联系；奥术、空间、时间也可以作为特殊学派。具体名称和归属待定。

### 冰的冻结与冰晶防御

核心体验是积累寒意、短时冻结和冰晶防御。水系偏潮湿、流动与减速，冰分支偏明确的控制窗口和冰晶实体；二者可以共享来源而保持不同构筑重点。冰分支是否继续接受水系加成需单独声明，不自动重复计入两系。

候选规则：寒意按目标记录，达到阈值后转为有限时间的冻结；冻结不无限叠加，首领可以缩短冻结时间或只受到减速。寒意阈值、衰减、抗性和控制间隔需要调参。冰箭和冰霜新星保留原 ID，并在内容文档归入冰分支草案。

法术可包括冰箭、霜环、冰晶护甲、冰墙和冰灵。冰墙按建筑规则检查占地与路径，冰甲属于护盾而非额外角色生命。成长可以提高寒意效率、护盾、控制覆盖或碎冰伤害，硬控时间须独立设上限。

联动候选：金系攻击命中冻结目标产生碎冰；水系潮湿帮助积累寒意；火系是否解除冻结并转为蒸汽效果待定，不自动建立互相抵消规则。

### 毒的叠层与有限传播

核心体验是对高生命目标叠加持续伤害，利用有限传播处理成群敌人。火偏即时爆发和地面灼烧，暗偏削弱与汲取，毒偏可读的毒层与感染。

原型候选：每目标的同类毒记录层数、单层伤害和到期时间，先试最多5层，每次命中只增加允许的层数并刷新对应持续时间。不同施法者共用还是独立计算上限待定。感染最多传播到2个邻近合法目标，传播不再次触发传播，不能造成无限连锁。

法术可包括毒针、毒雾、感染印记、毒蜂和毒灵。毒灵和毒蜂是两种不同召唤，分别保留精灵与动物标签。持续毒的每次伤害保留来源，用于击杀与经验归属；已经死亡的目标不能重复结算。

成长可以影响毒伤、层数上限、持续时间或传播效率，但不默认同时增加所有维度。机械、建筑等是否可中毒由目标标签与游戏规则决定，不从外观推导免疫。

### 奥术学派的魔能与专注

这里的奥术学派指奥能、魔能等法术属性，与放大、双倍、分裂等“奥术修饰单元”分别表达。通用修饰单元可以作用于多个学派，不因为名称相同而全部归属奥术学派。

核心体验是稳定魔弹、蓄力、法力管理与魔能护盾。法术可包括奥术弹、聚能射线、魔能护盾、奥能法阵与奥术精灵。聚能射线是法术，不等同于现有聚能修饰奥术。

奥能法阵可以作为持续区域提供资源支援；法阵是否是可受击建筑需另行声明。资源回复只能作用于合法资源池，同一来源加成不重复计算；对自身供能与消耗的循环需要有上限，不能通过双倍等效果生成无成本无限施法。

成长可以影响蓄力时间、单体输出、护盾转化和资源效率。是否引入专注或奥能层数作为额外资源待定，原型可以先沿用已有法力候选系统。

### 空间的部署与转移

核心体验是改变合法位置、弹道出口和战场距离，而非单纯增加移速。法术可包括折跃、牵引裂隙、折射门、空间刃和空间精灵。

折跃只作用于可移动、可转移且仍存活的实体。目标与目的地都必须合法，不能把敌人移出地图、越过领地攻击线后直接算清场，也不能把固定建筑当移动单位。传送不创建新实例，不重置生命、持续时间或召唤数量。

折射门作为成对的空间节点候选，两个出口都验证成功才创建。投射物经过后仍保留伤害来源、剩余寿命与命中记录；原型可限制每个投射物最多通过一次门，禁止门之间循环刷新射程。节点是否可受击、属于建筑还是持续效果待定。

成长可以影响部署距离、转移对象、节点存续和资源效率。空间效果不改变法杖编辑网格，也不绕过占格、配方和背包规则。

### 时间的局部节奏与有限回溯

核心体验是调整目标的行动节奏、法杖冷却和延迟效果。法术可包括时缓、法杖加速、延时爆裂、回溯护佑和时灵。

时间分为战斗模拟时间、目标局部行动时间、服务请求与事件时间三类。游戏暂停冻结战斗模拟；时间法术只改变声明的行动或冷却，不改变现实连接超时、奖励记录、经验账目、波次编号和其他玩家的控制流程。

时缓可以降低敌人的移动与攻击频率，法杖加速可以提高指定法杖的冷却恢复速度。二者需要明确与已有急速、减速如何组合，并限制最短冷却与极端行动倍率；不默认让持续伤害、召唤寿命和建筑寿命也一起加速或减速。

延时爆裂登记一次效果，时间到达时只执行一次，网络重试不重复登记。目标提前死亡时可在最后合法位置触发，或取消并返还部分资源，具体选择待定。

回溯护佑先尝试“记录单个合格友方在短窗口内的净损失生命并扣除期间已发生的治疗，窗口结束后有限恢复”的效果，而非恢复世界存档。不会复活已经退场的实例、返还消耗、重新领取奖励或复制物品；治疗目标、上限与增幅计算仍待确认。

成长可以影响局部节奏、窗口、延时收益或保护上限。全局时间停止、世界回档与波次倒退属于更大机制，当前未纳入本批法术。

### 扩展分支的成长与知识边界

五个方向都补充对应精灵候选。是否沿用同一召唤容量、是否需要专门资源和是否与已有学派并列待定。冰和毒的状态、空间的合法区域、时间的行动倍率与奥能资源都应在玩家已知范围内可解释；Agent 预览不能因此查询未发现能力或未来未公开波次。

新增内容与原有法术、奥术、法杖、角色的等级和品级机制兼容。成长预览展示适用对象、实际效果与代价；不能把高品级自动解释为永久冻结、无限传播、无限传送或无限加速。

## 亡灵学派与相关生命灵魂方向草案

### 分类与核心循环

亡灵适合独立表达为召唤与资源循环学派，主题包括白骨、魂灵、尸骸和役使亡仆。暗系侧重诅咒、削弱与汲取；木系侧重生命召唤和治疗；亡灵侧重形成军团、消费尸骸以及维护或转化亡灵单位。这些是内容定位草案，亡灵是否独立成系仍待定。

属性、学派和召唤家族分别保存。例如某个法术可属于亡灵学派、造成游戏定义的某种伤害，并生成骷髅家族单位；不把所有亡灵攻击默认等同于暗伤害。魂灵可作为亡灵主题的精灵候选，是否归为元素精灵由召唤家族配置决定。

候选循环为“基础攻击或法力召唤 → 击败有效敌人 → 留下尸骸或魂能 → 起尸、尸爆或强化亡灵 → 持续战斗”。原型可以先做尸骸，魂能作为后续资源候选，不要求同时引入两套额外资源。基础骷髅召唤可以只消耗法力，避免开局没有尸骸就无法运转。

### 法术与实体候选

| 类型 | 内容候选 | 构筑作用 |
|---|---|---|
| 直接攻击 | 骨矛 | 为开局提供输出，支持有限穿透 |
| 常规召唤 | 骷髅卫兵、骷髅弓手 | 前排近战与后排远程分工 |
| 尸骸利用 | 起尸 | 消费一个合格尸骸，生成模板化亡仆 |
| 尸骸爆发 | 尸爆 | 消费尸骸造成范围伤害，与起尸争夺材料 |
| 精灵候选 | 魂灵 | 提供远程攻击与后续魂能联动空间 |
| 建筑候选 | 墓碑 | 为本人亡灵提供有限维护或阵地支援 |

尸骸不是背包物品，也不是符文合成材料。起尸属于战斗施法，与“在法杖上把法术合并为符文”是不同机制。亡灵单位先按临时战斗实体处理，常驻角色复活、角色奖励和本局失败后的继续规则分别设计。

### 尸骸魂能与复生边界

- 候选尸骸带独立 ID、来源死亡事件、位置、剩余存在时间、是否已消费和可用标签。是否每个敌人都留尸、Boss 是否可留尸以及尸骸持续时间待定。

- 原型建议只有游戏明确标记的有效敌方死亡产生可用尸骸或魂能。友方临时召唤物死亡、自然到期或主动牺牲不默认返还完整召唤成本；特殊返还需要独立能力和上限。

- 多角色争用同一尸骸时，提交前同时校验资源、尸骸与召唤容量。成功只消费一次，失败不扣费；重复请求不生成第二只亡灵。

- 起尸生成新的亡仆实例，并记录原尸骸来源。原型使用受控模板，不完整复制原敌人的 Boss 技能、装备、等级或未公开数据。

- 原敌人死亡后的经验和金币已经结算。起尸不重放原击杀事件；友方亡仆再死亡不作为原敌人再次奖励。

- 尸爆也会消费尸骸，已用于起尸的尸骸不能再尸爆。是否产生新的可用尸骸必须显式定义，不能自然形成无限循环。

- 战斗暂停同时冻结尸骸、亡灵、墓碑和魂能相关战斗计时；波次结束是否清理尸骸与临时亡灵待定。

- 木系生命治疗、亡灵维护、建筑修理与护盾分别表达。亡灵能否接受普通治疗、是否受光系额外影响由目标标签和规则决定，不从阵营名称自动推导。

- 普通 Agent 只可读取玩家已知的尸骸与复生预览，不因起尸获得隐藏敌人图鉴或技能资料。

### 成长与军团管理

角色、法术、法杖和奥术修饰可影响亡灵生命、伤害、存续时间、资源效率、起尸效率与维护效果。军团数量适合作为少量关键节点的候选，仍受共享或专用召唤容量约束。尸骸转化数量、魂能上限、牺牲与返还分别配置，不随等级默认无限增长。

角色候选为死灵术士，法杖候选为骸骨法杖；奥术修饰可提供役使延时，符文配方可形成重甲亡灵或骷髅军阵。是否需要手动指挥、集火、遣散与主动牺牲，以及它们的界面和 Agent 操作仍待定。

### 相邻方向

血法、灵魂、精神与契约与亡灵有联动空间；这些方向与幻术、炼金、符咒、机械、重力、音律、星象和命运一起在下一节分别比较。它们可以共享主题，但不默认共用尸骸资源或亡灵免疫规则。

## 更多机制学派候选

以下方向用于拓宽构筑体验，均为机制草案，不是已经确定的首版清单。元素属性、施法学派、玩法类型与召唤家族分别表达，可以组合而不必把每种主题都定义为新的伤害元素。

例如机械学派可以制造火属性炮台，契约学派可以召唤冰属性契约兽，重力学派可以产生暗属性力场。某个具体法术是否具备多个属性、是否允许跨系加成，仍由内容配置和游戏规则决定。

| 方向 | 独特玩法 | 成长维度 | 实现依赖与取舍 |
|---|---|---|---|
| 血法 | 以明确的生命代价换取护盾、爆发或维持召唤 | 代价效率、护盾转化、风险窗口 | 先明确谁可支付生命、保底生命与不可支付时的处理 |
| 灵魂 | 积累魂能、附加魂印，转化为保护或支援 | 魂能容量、转化效率、印记持续 | 魂能为可选学派资源，合法来源与上限需明确 |
| 精神 | 改变目标选择、制造恐惧或临时影响敌方控制权 | 控制效率、持续时间、目标数量 | 需要仇恨、阵营与控制抗性规则 |
| 幻术 | 用诱饵、镜像与虚假威胁影响敌人决策 | 诱饵强度、存续、投影效率 | 需要可解释的目标选择与幻影标签 |
| 炼金 | 通过瓶剂、催化与地表材料形成即时效果和反应 | 配方效率、反应范围、消耗管理 | 消耗品、法力或学派库存采用哪种成本尚未确定 |
| 符咒与结界 | 预先布置有限触发次数的符印或持续结界 | 触发效率、覆盖、准备收益 | 部署位置、触发顺序、寿命与布置容量待定 |
| 机械与构装 | 管理炮台、构装单位与供能或过载代价 | 输出、维护、供能效率与协同 | 可与金系机关共用底座，热量或供能仅为候选 |
| 契约 | 以维持代价换取强力召唤或特定增益 | 契约效率、维持能力、契约兽协同 | 代价不足、提前解除、目标退场的结果需可预览 |
| 重力 | 用持续力场改变聚集、移动和空间压力 | 力场范围、控制效率、存续 | 与空间瞬移和风系推退区分，位移合法性共用 |
| 音律与共鸣 | 通过节拍、光环与有限施法事件积累触发效果 | 节奏收益、支援覆盖、连奏效率 | 需要明确计入连奏的原始施法事件与触发上限 |
| 星象 | 围绕环绕星体、延迟落点与阶段轮换规划输出 | 星体强度、轨道覆盖、阶段收益 | 星体是弹道、持续实体还是召唤物需区分 |
| 命运 | 通过有限次数的改运、印记与条件兑现影响本局结果 | 触发效率、有限充能与条件收益 | 与运气和奖励刷新衔接，具体权限属于游戏玩法 |

### 主题召唤与建筑表现

元素系可以使用对应精灵；机制学派也可以用契约兽、构装体、幻影、符灵、星灵等主题实体表达召唤。具体家族、是否有生命、占用哪类容量和能否生成死亡资源都需要显式声明，不能只按外观判断。

机械、炼金、符咒与星象都可能提供建筑、节点或区域效果。是否可受击、是否阻挡寻路、是否计入建筑数量分别配置。金木土的建筑偏向继续保留，不排除其他学派拥有少量特殊建筑。

### 组合与平衡草案

学派通过操作方式形成差异：精神改变敌方决策，幻术制造可交互诱饵；空间改变合法位置，重力持续改变移动；时间调节局部节奏，星象安排落点与阶段；音律按施法事件积累收益，命运按有限充能与条件兑现收益。

新学派优先复用目标校验、持续效果、暂停、召唤容量、资源事务和事件去重。每种学派只在需要时增加自己的资源，不要求全局同时出现魂能、鲜血、热量、药剂和契约值等所有资源条。

控制、复制、诱饵、回声、尸骸和奖励刷新需明确边界：临时转阵营保留实体身份；简化镜像不完整复制资源；回声不递归触发；学派代价只作用于游戏允许的对象；命运能力不绕过普通信息披露或作弊授权。

### 讨论与原型优先级草案

可先挑容易与已有系统组合的机械、符咒、重力和音律验证新构筑；精神和幻术需要敌人目标选择支持；血法需要生命支付对象；契约、灵魂、炼金和命运需要确定对应资源或奖励规则。最终选择仍待讨论，候选清单可以继续扩充。

## 召唤精灵动物与制造建筑的法术

**已确认方向**
召唤包括各系元素精灵与动物；制造建筑是法术类别之一。当前金木水火土光暗雷风各系都有对应精灵，金木土偏向建筑，木系提供更多召唤与治疗。具体条目、数值和运行规则仍为草案。

**机制草案**
两类法术都创建有独立实例的战斗实体，记录施法角色、来源法杖、来源法术、位置、生命或耐久、持续时间和数量上限分组。召唤精灵与动物可移动并承担攻击或辅助行为；建筑通常固定在部署位置，提供攻击、防御或资源支援。

建议这些实体先作为本局战斗单位，不直接计入奖励招募的常驻角色；是否有长期随从或永久建筑另定。角色的召唤与建造专长可以分别影响它们。

| 规则场景 | 原型处理草案 |
|---|---|
| 施放位置 | 召唤精灵或动物在游戏定义的合法生成区域出现；建筑使用合法部署点，并在施放前校验 |
| 位置无效或数量已满 | 常规自动施法等待条件恢复，不扣资源、不启动冷却；主动替换已有实体需单独操作 |
| 召唤物移动与建筑占地 | 精灵或动物按其行为寻找目标；建筑不得重叠禁建区或非法封死必经路线，前提是采用阻挡寻路机制 |
| 生命或持续时间归零 | 实体退场并释放对应容量，退场原因与击杀奖励分别处理 |
| 打开背包暂停 | 召唤物行为、建筑攻击、实体持续时间与战斗模拟一起暂停 |
| 双倍奥术修饰 | 可作为同次生成两次的候选，仍受位置、资源和数量限制 |
| 放大或分裂修饰 | 按法术适用标签定义；不自动把范围增幅解释为召唤物变大，也不自动让分裂作用于建造 |
| 换杖或角色离场 | 保留来源信息；立即消失、继续到期或部分失效的规则待定 |
| 波次结束 | 原型可尝试清理临时实体；跨波保留作为单独机制候选 |
| 增级与升品 | 召唤物或建筑从来源法术、角色等获得加成；生成时锁定还是实时跟随待定，不叠算同一加成 |

**待定**
元素精灵与动物是否共用召唤容量；召唤物与建筑上限按角色、法术或全队统计；持续时间与永久存在；手动指挥；是否吸引仇恨；阻挡与碰撞；治疗与修理对象；召唤物击杀的经验归属；被摧毁后的返还；建造是否能指定位置；跨波和跨角色的归属规则。

## 升级与品级的共通约定

**已确认**
法术、奥术、法杖和角色四类内容都具备升级机制与品级机制。同名同品质法术/奥术的二合一升品已确认，其余培养方式和完整品级效果尚未确定。物品成长不默认与角色等级同步；角色个人等级、击杀经验升级及奖励之间的关系仍需统一设计。

**机制草案**
建议分别保存实例等级和品级：等级描述该实例的培养进度，品级描述该实例的品质档位。两者的关系、上限及能否相互转化另定。品级与掉落稀有度是否一致也需明确。角色额外采用途径和序列描述晋升；其品级是否并入序列仍待定，不能默认三者都是独立数值成长轴。

| 对象 | 升级可影响的内容草案 | 品级可影响的内容草案 |
|---|---|---|
| 法术 | 伤害、治疗、状态强度、冷却或资源效率 | 基础属性、成长上限或额外效果 |
| 奥术 | 增幅强度、代价或适用条件 | 增幅特性、可修饰对象或成长上限 |
| 法杖 | 固有属性、资源效率或预留格解锁 | 可用区域、固有特性或成长潜力 |
| 角色 | 施法、资源、专长、召唤、建造或队伍支援能力 | 途径序列承载身份与关键能力，角色品级如何衔接待定 |

上表是候选维度，不表示升级必定增加格子、减少冷却或提升品级。

**场景处理草案**

- 升级前预览变化与成本，校验通过后一次提交，取消或失败不消耗材料；重复请求不重复扣费。

- 移动法术、更换法杖持有者时保留实例成长；合成产物的等级与品级继承需独立定义。

- 若成长会改变占格或开放区域，先验证当前布局，不能静默覆盖或丢弃其他内容。

- 普通 Agent 只能查询自己已知且允许操作的成长信息，不能借升级预览获取隐藏品级、法术或配方。

**已确认的同类升品**

- 同定义、同品质的两个法术或奥术可合并为一个，提升一档品质，不提升等级。
- 当前品质顺序为白板、精良、稀有、史诗、传说、神话，神话封顶。
- 拖到合法同类目标时只显示候选边框反馈，松手才合并；拖离或取消不合并，不弹操作提示。
- 背包与法杖均可参与此类升品，保留目标位置与旋转；不因合并或移动重置施法冷却。
- 此规则与下节“法杖内识别配方并合成符文”分开，不能把配方位置限制套用到同类升品。
- 当前原型产物保留较高实例等级，品质具体倍率是可调整数值，非最终平衡。

**待定**
等级上限、升级材料与费用、能否直接提升品级、品级与稀有度的关系、成长是否改变形状、法杖扩槽是否独立于升级、物品成长是否跨局保留、升级是否可在背包内进行、符文是否沿用同一套成长机制。背包禁止符文合成是已确认规则，不能据此直接判定所有升级操作的位置限制。

# 6 符文配方与合成

**已确认**

- 特定单元与空间排列可以触发组合效果。

- 玩家可以选择是否把符合条件的组合合并为符文。

- 合成结果可以改变占格布局。

- 火花与放大奥术可以构成火球的设计例子。

- 背包中不识别为可执行合成，材料必须处于法杖上。

**机制草案**
合成分为“识别配方 → 展示已允许披露的信息 → 预览结果 → 选择放置 → 一次提交”。提交同时验证材料、资源、配方条件和产物位置。任何条件失败时，材料、位置与消耗全部保留。

| 场景 | 处理方案 |
|---|---|
| 产物形状比材料更大 | 显示新形状，允许重新选位置；放不下就不消耗材料 |
| 同一材料匹配多个配方 | 展示可选择的候选，不自动替玩家消耗 |
| 相邻单元同时提供增幅 | 区分未合并布局效果和合并后效果，明确收益变化 |
| 配方允许旋转 | 按整体相对布局匹配；镜像需独立声明 |
| 合成时材料被移动 | 重新校验并拒绝过期操作 |
| 玩家取消或界面关闭 | 回到提交前状态，不产生半成品 |
| 未发现的配方 | 是否展示未知组合、允许盲试或提示结果，由游戏发现规则决定 |

**待定**
合成是否可逆、是否有额外费用、产物等级与品级如何继承、多材料消耗数量、跨法杖合成、符文能否作为下一层材料、配方发现方式。跨杖合成尚未被允许，不能从“都在法杖上”推导出来。

# 7 经验奖励与经济

**已确认**

- 击败怪物必定获得经验，积累经验升级，升级提供奖励。

- 升级具体奖励内容尚未确定。

- 每轮胜利有两类收益：成长或补给奖励，以及随波次增加的基础金币。

- 成长奖励可包括生命、防御、攻击倍率、施法速度、距离、范围、运气、结算金币加成等；也可以直接给金币或回复生命。

- 怪物有概率掉落金币，概率受运气影响。

- 角色可以成为奖励；不同 Boss 可掉落法术、奥术、物品和装备。

**机制草案**
| 来源 | 建议职责 | 确认状态 |
|---|---|---|
| 击杀经验与升级 | 提供新法术、奥术或已有内容强化的构筑机会 | 奖励职责待确认 |
| 波次成长奖励 | 提供全局属性、经济或恢复选项 | 类型已确认，选择方式待定 |
| 波次基础金币 | 固定发放，随波次成长 | 方向已确认，公式待定 |
| Boss 战利品 | 提供特殊内容、角色或装备 | 部分类型已确认，角色来源待安排 |
| 商店或事件 | 消耗资源、补全构筑 | 后续候选 |

奖励可先尝试三选一，但并非既定规则。升级是立即暂停领取，还是积累到波间领取，也尚未确定。多角色已确认各自保存经验与等级；当前将经验归属实际击杀角色，其他辅助或贡献来源仍待设计。

**边界处理草案**

- 连续升级应保留每次应得奖励，不用一个弹窗覆盖前一个。

- 背包或角色容量不足时，保留待领取内容，提供明确处理入口。

- 领取和扣费采用唯一操作标识，网络重试不重复发放。

- 随机奖励一旦生成，返回界面不重新抽取；是否允许付费刷新另定。

- 运气只影响声明的概率和品质，不默认改变所有随机过程。

**待定**
金币用途、商店、刷新与出售、基础收益曲线、运气公式与上限、稀有度、经验曲线、奖励池偏向当前构筑的程度。

# 8 怪物难度与首领

**已确认**
怪物会随时间或轮次提升数量、生命、攻击、攻击速度等。每 5 波有小 Boss，每 10 波有大 Boss，每 100 波有顶级 Boss；Boss 属性也随波次增强，不同 Boss 可有不同掉落。

**机制草案**

- 波次生成、怪物模板与成长曲线分开定义。同一种怪物可以出现在多个强度档位。

- 先尝试按最高等级安排首领：100 波优先顶级 Boss，10 波优先大 Boss，5 波安排小 Boss。是否替代还是叠加仍需确认。

- 难度同时使用阵容变化与数值增长，避免仅靠全属性持续相乘。

- 数量、生命、攻击和攻速使用独立曲线；远程、护盾、快速敌人逐步加入。

- 首领战利品可叠加于基础波次奖励；是否固定保底、随机抽取或掉落角色另定。

**待定**
按现实时间还是轮次成长、出怪节奏、路径与碰撞、敌人是否攻击角色、控制抗性、召唤物是否计入清场、Boss 技能阶段与掉落概率。

# 9 场地天气与图鉴

**后续扩展**
希望加入场地、天气等系统，让每局有更多 roguelike 变化；未来可能提供图鉴。

**机制草案**

- 场地表达持续的地形或环境规则；天气表达一段时间内的外部变化。

- 环境可以影响移动、法术或状态，但每种效果需要清楚说明对象与来源。

- 提前预告已经允许玩家知道的下一轮环境，支持针对性调整。

- 图鉴区分已拥有、已见过、已研究等知识状态；具体层级由游戏决定。

**待定**
首版环境范围、环境变化频率、元素联动、环境是否伤害领地、图鉴解锁条件、未知条目是否显示轮廓或数量、首次合成是否自动解锁说明。

# 10 Agent 交互与远程会话

**已确认方向**

- Agent 应能通过稳定接口游玩，减少查找界面节点和模拟拖拽。

- 接口应支持状态读取、能力发现、动作执行和事件订阅。

- 希望提供 CLI 与 Skill，并形成较通用的交互协议。

- Playwright 与 CDP 都不是协议必需依赖；浏览器控制能力可由外部环境提供。

- HTTP 服务作为希望采用的远程接入方向，支持 IAB、桌面和手机中的游戏会话。

- 内部 UI、素材与实现改变时，尽可能维持外部协议兼容。

**机制草案**
手机或浏览器中的游戏主动连接会话服务；Agent 通过同一服务访问被授权的游戏会话。HTTPS 请求负责查询与操作，事件流负责下发通知。HTTPS 加 SSE 是候选实现，传输、服务器和协议消息格式尚未定稿。

通用层只统一能力描述、参数格式、上下文、调用结果、状态版本和事件；法杖、配方等语义由游戏适配器声明。CLI 使用能力清单提供调用入口，Skill 指导 Agent 发现并使用当前能力。工作名 Playlink 不代表已有正式发布产品。

| 接口能力 | 本游戏的示例 |
|---|---|
| 会话与能力发现 | 当前对局、版本、支持的操作及参数 |
| 状态读取 | 队伍、法杖、背包、战场、奖励 |
| 操作预览 | 放置是否可行、合成消耗和结果 |
| 动作执行 | 移动、旋转、合成、选择奖励、开始波次 |
| 事件订阅 | 领地受伤、低血量、升级、首领入场、波次完成 |
| 结果与恢复 | 命令状态、事件补读、断线恢复 |

**边界处理草案**

- 区分服务已接收、游戏已执行、失败、取消、过期，离线时不能把排队当成功。

- 指令含唯一请求 ID、目标会话和必要的状态版本，重复投递不产生重复收益。

- 事件含会话、序号与状态版本；断线后按游标补读，历史过期则重新读取状态。

- 高频受伤事件可合并；低血量通知按阈值跨越触发，恢复后重新启用。

- 页面回调、服务推送和模型唤醒分别处理；外部 Agent 宿主负责接收事件并启动决策。

- 人与 Agent 同时操作时，需要控制权或冲突处理，具体方式待定。

- 手机后台页面可能暂停；原型按前台运行设计。若要锁屏继续战斗，需要另行选择服务器模拟等方案。

**待定**
协议与 CLI 名称、版本策略、服务部署、身份配对、连接生命周期、状态同步频率、事件保留时间、命令超时、Agent 是否可申请特定事件时暂停。

# 11 信息披露与游戏决定的特殊能力

**已确认**
普通接口只能返回当前玩家按游戏规则已知的信息。拥有和知道是两个概念，未拥有但已见过的法术可以属于已知信息。不能通过正常目录、图鉴或能力参数一次获取全部未发现法术。

可以提供玩家解锁或允许的作弊能力，例如补满生命、获取指定魔法。具体选项、解锁条件、授权范围、次数和其他规则全部由游戏决定，通用协议只负责声明、查询、调用和通知。

**机制草案**

- 所有输出使用同一套知识与授权判定：状态、能力清单、参数枚举、配方预览、错误、日志、事件、搜索、自动补全、缓存及回放。

- 猜测隐藏 ID 时，返回不泄露其存在与详细内容的失败信息；具体文本由游戏决定。

- 配方预览不得绕过发现规则，是否允许盲合由游戏机制决定。

- 普通查询不允许 Agent 自行选择全知视角。调用者身份与授权由受信任的会话上下文确定。

- 作弊可作为能力分类，不强制每个游戏实现固定的 cheats 模块。

- 解锁补血不自动赋予全图鉴或隐藏配方查询权限。若游戏允许额外披露，作为独立能力表达。

- 普通结果不混入其他玩家、其他对局或高权限查询缓存。撤销授权后重新计算可见能力。

- 是否记录或标记使用作弊，由游戏决定。

**场景检查**
| 场景 | 应满足的结果 |
|---|---|
| Agent 查询未发现法术目录 | 只得到游戏允许披露的条目或占位信息 |
| 参数 Schema 提供物品候选 | 不包含无权知道的名称与属性 |
| Agent 猜中隐藏物品 ID | 不因失败细节泄露隐藏信息 |
| 解锁补血能力 | 仅增加游戏实际授予的能力 |
| 图鉴发现新法术 | 更新已知信息，并可产生能力或知识变化事件 |
| 权限失效 | 后续查询和调用按新权限执行 |

**待定**
知识属于账号、队伍、角色还是本局；图鉴是否跨局保存；作弊知识撤销后的处理；不同玩家协作时的信息共享范围。

# 12 素材表现与实现边界

**已确认**
前期允许使用名称、文字、图标和简单形状。正式素材后续可替换，不能与游戏规则写死在一起。游戏以 Inkra 使用方角度选择组件。

**机制草案**

- 逻辑定义、实例状态与表现配置分开。内容 ID 关联文字、图标、图片、动画、音效或自定义渲染。

- 角色和怪物可先用名称与血条表示；法术直接展示真实占格；弹道和范围用基础形状表达。

- 表现配置支持尺寸、锚点、朝向和动画状态；缺失素材回退到名称或图标。

- 逻辑碰撞、施法范围、占格和选择区域单独定义，不依赖图片透明边距。

- 更换素材不改变实例 ID、存档引用和 Agent 操作标识。

- 界面提供暂停、选中、作用范围、增幅来源及失败原因等可读反馈。

- 高频战斗更新与面板更新分开，避免所有界面每帧重绘。暂停后不继续执行战斗计时。

**待定**
正式美术方向、音效、动画规格、可替换资源包格式、移动端布局、目标帧率与设备性能预算。

下表是讨论优先级建议，不代表已经批准的开发排期。

| 优先级 | 决策 | 影响 |
|---|---|---|
| P0 | 多角色是否同时上阵，多根法杖如何施法 | 战斗模型、界面与资源归属 |
| P0 | 角色与领地的生命关系，角色是否移动 | 目标选择、伤害和失败条件 |
| P0 | 法杖初始形状、背包形式、旋转规则 | 最核心的编排操作 |
| P0 | 双倍奥术叠加、消耗与循环限制 | 战斗正确性和组合强度 |
| P0 | 角色途径、序列称号与晋升要素 | 角色身份、法术装备成长与进阶门槛 |
| P0 | 升级奖励细节、领取时机及个人经验的辅助获取途径 | 战斗节奏和成长结构 |
| P0 | 合成事务、材料继承与跨杖限制 | 物品完整性和构筑策略 |
| P1 | 法术、奥术、法杖、角色的升级方式及品级规则 | 内容成长、资源消耗与奖励价值 |
| P1 | 召唤动物与建筑的归属、数量和跨波保留 | 战场实体、路径与资源平衡 |
| P1 | 属性归属、精灵行为与跨系限制 | 法术、角色与建筑的内容分工 |
| P1 | 金币用途、奖励池、角色获取与容量 | 成长和经济平衡 |
| P1 | Boss 替代或叠加、难度增长曲线 | 无限波次节奏 |
| P1 | HTTP 会话、事件、控制权与知识范围 | Agent 与远程游玩 |
| P1 | 冰毒状态、奥能资源、空间部署和局部时间边界 | 扩展学派的可解释性与战斗正确性 |
| P1 | 亡灵军团、尸骸消费与魂能返还 | 召唤容量、资源循环与奖励去重 |
| P2 | 天气、场地、图鉴和正式素材 | 后续内容扩展 |

## 奖励刷新、采集与幸运（2026-11-04 最新确认）

本节记录本次已确认并接入试玩的机制，不改变前文其他草案的状态。新增显式奖励刷新操作用于换一组候选；重新加载页面仍恢复已有候选，不触发重抽。

**奖励刷新**

每波免费刷新次数为`floor(max(0, wave) / 10)`：第1–9波没有，第10–19波每波1次，第20–29波每波2次，依此增加。每进入新波恢复该波免费额度，未用额度不结转；同波存档恢复保留已用次数。免费优先使用，不增加付费次数。

付费刷新次数在本局全局累计，跨波不重置；下一次付费价格为`3^paidCount`金币，即1、3、9、27……。只有重开新局才把本局付费次数和刷新总次数归零。超过安全整数范围的价格不能支付，剩余免费次数仍可使用；刷新总次数达到安全上限后停止刷新，避免候选ID重复。

刷新只允许在奖励阶段且已有候选时执行，每次生成四张组内语义不重复的新卡。校验当前奖励组、可用次数和金币后，扣费、计数、随机序列与新候选一次提交；拒绝时不扣费、不消耗次数或随机数。成功后整组旧卡及旧奖励组标识失效，过期点击或远程领取/刷新请求不能领取新卡；同一命令ID重试返回原结果，不再次扣费或换卡。候选、随机序列、免费已用次数、全局付费/刷新次数及幂等记录随checkpoint保存，恢复不会自动重抽或重置同波额度。

**采集与金币收入**

全队采集百分比为当前队伍各角色基础采集之和，加各自实际装备提供的采集之和，再加一次本局全队采集奖励。全队奖励不按角色或法杖数量重复相加，未装备的采集符不提供加成。金币收入倍率为`1 + 全队采集百分比 / 100`。

怪物掉落金币、清波保底金币和金币奖励卡共用同一个正收入结算入口。每笔实际到账为`floor(基础收入 × 倍率 + 上次小数余量)`，不足1金币的部分保留到下笔收入，并随存档保存；例如10%采集下，连续十笔1金币收入共到账11金币。统计只累计实际到账一次，不在事件消费时再乘倍率。刷新、修复、升级等金币支出按原价扣除，不享受采集加成，也不消耗该收入余量。

幸运与采集分别作用于概率和金额：幸运提高击杀金币及装备的掉落概率，现有首领装备保底继续生效；采集放大已经产生的金币收入，不提高掉落概率，不增加装备数量，也不改变奖励或装备的品级抽样。

## 召唤与建筑进入当前demo（2026-11-04 最新确认）
