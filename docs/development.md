# 并行开发与验收

根协调者：本聊天，负责仓库、共享接口、依赖、运行时组合和最终提交。
四模块独立任务：战斗/构筑/界面/HTTP。负责人自行拆分至少两个可独立执行的小任务，
分配明确文件，使用原生独立聊天；同一共享 checkout，禁止同时写同一文件。
先读 task 文件。创建子任务时传递此 AGENTS 授权、仓库绝对路径、目标、
文件边界、契约、验收场景、禁止事项和报告要求。
没有注册本仓库项目时可创建 projectless 聊天，提示进入已存在绝对路径工作，
不要选用其他不相关项目。不请求 worktree，不自行切分支。

模型：Sol 负责战斗/构筑/协议及所有非 Sol 工作验收；Terra 界面；
Luna 明确执行；OpenCode Go deepseek-v4-pro 可承担中等实现。
Flash 从模型池排除。各模块初始最多 2 个子任务并行，按依赖收敛，
不要为每一个微小函数创建任务，也不要让昂贵负责人空转轮询。
provider 支持情况在派发前确认；保留 operationId，结果不确定先查询不重复创建。

交付应包括：目标完成情况、代码分层/调用流程、如何运行、实际验证和未验证项。
Sol 以实际代码审查为主，可批量验收；按风险补运行验证，不要求每项都运行。
非 Sol 工作未通过 Sol 验收不能标完成；界面视觉必须标为等待用户确认。
根协调者最终检查试玩闭环并提供本地预览。
