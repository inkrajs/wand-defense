# 战斗渲染调研：2026-11-06

## 范围与环境

用户反馈的是怪物和技能特效较多时的战斗卡顿。下面分别记录完整游戏压力场景和单独的精灵绘制对照，不能把两者的数据直接当成同一种测试。

环境：macOS，Apple M3 Pro，Headless Chrome 156，DPR 1；WebGL 使用 ANGLE Metal。浏览器使用隔离地址和合成存档，没有读写玩家的游戏存档。项目自带的 `scripts/measure-combat.mjs` 构造固定随机种子的战斗数据，其中有 60 个敌人、100 个初始投射物、3 个角色和 6 根法杖。为持续观察，浏览器压力测试提高了敌人生命值。

## 完整游戏：攻击动画重建

怪物攻击动画原先通过改变 React key 重建图标节点。Inkra 的 `PencilIcon` 有有限的图像缓存，但节点重建仍会创建新画布和执行复制，缓存未命中时还需要重新绘制。现已保留画布节点，交替播放等价的攻击动画；连续攻击时也能重新触发。

两轮隔离压力测试均使用 60 个在城墙处持续攻击的敌人，统计首 4 秒之后：

| 测试 | 观察窗口 | 原版图标容器移除次数 | 复用版移除次数 | 原版／复用版帧间隔 P95 |
| --- | --- | ---: | ---: | --- |
| 第一轮 | 约 11 秒 | 1120 | 0 | 16.8 / 16.8 ms |
| 第二轮，反向顺序 | 约 8 秒 | 800 | 0 | 33.3 / 16.8 ms |

两次结果表明节点重建已避免，但帧间隔波动较大，不能据此给出整体 FPS 提升比例。构建及 24 项相关检查通过；浏览器检查确认同一节点在连续快速攻击时保持不变，且两套动画均能播放。

在另一次将 60 怪和 100 个投射物同时放入初始画面的冷启动采样里，最大主线程任务约 4 秒；堆栈集中在 Inkra 图标路径采样和图像像素处理。这是极端合成场景的单次结果，不代表普通波次必然卡 4 秒。怪物首次绘制、技能纹理生成和高负载效果仍需进一步分析。

## 绘制方式对照

在隔离画布中，取出游戏实际渲染的 32 个怪物图样和 16 个火焰、水、风、雷、命中、领域、圆环等技能纹理，预先生成位图，再分别用 DOM 图片、Canvas 2D、OffscreenCanvas + Worker 和 PixiJS / WebGL 绘制相同运动场景。每轮为 60 个怪物加 400 个效果，180 帧，正反顺序各运行一次。

| 方式 | 帧间隔 P95 / P99 | 观察 |
| --- | --- | --- |
| DOM 图片 | 约 16.8 / 16.8 ms | 已将绘制结果作为位图复用；没有包含实际 React 更新 |
| Canvas 2D | 约 16.7–16.8 / 16.8 ms | 同一画布绘制已生成的位图 |
| OffscreenCanvas + Worker | 约 16.7–16.8 / 16.8 ms | 两轮均发送并完成 180 帧；主线程时间不包含 Worker 和 GPU 的全部成本 |
| PixiJS / WebGL | 约 16.7–16.8 / 16.8 ms | 基于实际纹理的精灵；未做图集打包 |

该场景接近显示器的 60 Hz 上限，无法区分各方式在完整战斗中的优劣。DOM 对照是简化图片层，不是当前完整 React 战斗；这些样本没有碰撞、血条、完整区域特效、存档、输入交互，也没有覆盖手机、高 DPR、弱 GPU、内存或耗电。前一轮 300 个圆点的测试同样只能说明简单场景跑满刷新率。

## 后续方向

1. 保留手绘外观，先针对战斗首次出现的怪物和技能纹理验证预绘制、缓存容量、图集和复用，避免路径采样进入关键帧。缓存需要按图样、尺寸、主题和纹理种子区分，并设定内存上限。
2. 以真实游戏状态建立可切换的视觉层原型，优先对照 Canvas 2D 与当前实现；只有在同等效果下验证有效才迁移。按钮、背包等交互继续保留可访问的 DOM。
3. 如果主线程绘制仍是瓶颈，再测试 Worker + OffscreenCanvas；同时测量数据传递、实际出帧、资源开销和不支持时的回退。MDN 建议对重复图形预绘制并复用：[Optimizing canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)。
4. 在数量、混合和透明层压力更大时继续与 PixiJS / WebGL 对照，并测试图集、显存和弱设备表现：[PixiJS Performance Tips](https://pixijs.com/8.x/guides/concepts/performance-tips)。

对照应包含桌面和手机、冷启动与稳定战斗、P95/P99 长帧、主线程与 GPU 时间、内存和视觉一致性；避免只比较峰值 FPS 或测试简单图形。
